## v0.3.0, 2026-10-15

- 2026-10-15: released. `--version` prints `siwithin 0.3.0`; the smoke test passes 244 checks with fake CLIs. The proxy and the kill walk ran live in the red passes of 14 and 15 October 2026 (`tests/red/scorecard-2026-10-14-4.md`, `tests/red/scorecard-2026-10-15.md`; README, Tests): the five 0.2.1 walls held, the budget stop fired by design, `env-key` held, and `outlive` held with `outlived 1` after the walk fix below. README and SECURITY.md are rewritten for 0.3.0: the key gap is closed for the proxy adapter and stays open under `auth = "env"`, the detach and verifier gaps and `--budget nan` are closed, and the transcripts gap, the proxy's missing ceiling check, unpriced paths and models, and `deny_exec` by path stay open (SECURITY.md, "Known gaps"). Not yet confirmed live: the proxy's 402 at the budget, and paths other than `/v1/messages` in a longer run.
- 2026-10-14: the key proxy, the first feature of 0.3.0; `--version` still prints 0.2.1 until the release. A read of the whole code as a stranger that day found that the run holds the API key: it is in the environment of every command the run starts, so a request made by hand, or through a second CLI the run starts, is spend that no stream shows and no budget counts, and the key can be sent anywhere, since the network is open; and a key helper named in the config directory's `settings.json` can be read and run inside the fence. Now the runner keeps the key and the run gets a token. For an adapter whose new field `auth` is `"proxy"` (the first adapter, claude), the runner reads the key before launch, from the adapter's key variable (`ANTHROPIC_API_KEY`) in its own environment or else from the first line printed by `[auth] key_command`, outside the fence, and starts a small HTTP server on a loopback port of its own, standard library only. The run's environment holds `ANTHROPIC_API_KEY=siwithin-<32 characters>`, new for every run and worth nothing elsewhere, and `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>`; the real key is in no file the runner writes, no log line and no error message.
- Every request the run makes, however it makes it, passes that one door. The proxy takes only the run's token (in `x-api-key` or as a bearer; anything else gets 401 and goes nowhere), forwards the request to `[auth] upstream` with the real key, relays the response as it arrives so a streamed event reaches the CLI when it is sent, and prices each `/v1/messages` response at the `[prices]` rates from its usage, read as it passes. One line per request goes to `proxy.jsonl` in the run's folder (path, model, status, usage, cost, the running total, the client's port, why it was refused; never a body, a key or the token). Once the total reaches the budget every later `/v1/messages` request gets 402, the first refusal kills the CLI's process group as the streamed stop does, and the proxy keeps refusing until the runner exits, so a process that outlived the kill, in a session of its own or started by a second CLI, can spend nothing. When the run ends the proxy is sealed, its log closed and its server shut, so the token is worth nothing.
- The figures: with the proxy on, the ledger line's `true $` is the proxy's total, what left the machine for the API through the only door, and a killed run is booked at it, not at a ceiling. `summary.json` gains `proxy_cost`, `proxy_requests` and `proxy_refused` (null without a proxy), and keeps `stream_cost`; the streamed stop stays as a cross-check and still kills on its own count, and a summary note `stream $x, proxy $y` appears when the two differ by more than a cent and more than 1%. The receipt's `files` gains `proxy.jsonl` on runs that had a proxy, and `--verify` checks it like the rest. With `--require-api-key` the init event's key source must be `ANTHROPIC_API_KEY`, the token's variable.
- New checks before launch. A `settings.json` in the run's config directory that names `apiKeyHelper` is refused: the helper is readable by the run, so it belongs in `[auth] key_command`. No key for the runner is refused (a dry run warns). An `[auth] upstream` that is `http://` and not a loopback host is refused, since the real key goes there. `--dry-run` prints `auth: proxy 127.0.0.1:<port>` and starts nothing; `command.txt` holds the real address.
- Config: a new `[auth]` section (`key_command`, `upstream`, `upstream_timeout`) and four adapter fields, `auth`, `key_env`, `base_url_env` and `key_header`, with their built-in values in `config.example.toml`. The claude adapter's `env_pass` no longer lists `ANTHROPIC_API_KEY`. `auth = "env"` under `[adapters.claude]` keeps 0.2.1's behaviour, the key in the run's environment, with a warning in the checks. The proxy serves the first adapter only in this release: the Codex adapter keeps `auth = "env"` and is otherwise as it was.
- Not done in this release: a ceiling check that would refuse a request whose worst case crosses the budget (the wall stops the request after the one that crosses it, so one response can pass the budget by its whole cost); a price for a model that is not in `[prices]` (its responses are logged unpriced, and the run's `true $` takes the CLI's own figure for it); metering of paths other than `/v1/messages` (those on `[auth] paths` are forwarded and logged, not priced; see the allowlist below). The smoke test passes with the proxy's checks, against a fake upstream and a fake CLI on loopback; no live CLI has been run through the proxy yet.
- 2026-10-14: the walls, the second stage of 0.3.0, from the four things the stranger's read of that day found that the proxy does not close, and one the proxy's own report added; `--version` still prints 0.2.1. The kill walk: a stop was one `killpg` of the CLI's process group, so a process the run started in a session of its own outlived the budget kill, the timer and the ledger line, with the network, and held the runner's read loop open if it held the CLI's stdout. Now the runner keeps the set of the run's processes: every two seconds while the CLI lives, and at every stop before the group is killed, it reads `ps -A -o pid=,ppid=,stat=` and adds every descendant of the CLI, and after the CLI's exit and after each kill it reads the table again and reads `ps -E -A` for any process of the user whose environment carries the run's marker (the adapter's `tmp_env` value, `{run}/tmp`, unique to the run; for an adapter without one, the `config_dir_env` value with the run's base URL), keeping the pids and nothing else, never writing an environment it read. On every stop (`budget`, `key`, `timeout`, `interrupted`, SIGTERM) and after the CLI's own exit: SIGKILL to every pid in the set, then the group kill, then the walk again, up to five times 200 ms apart, until nothing in the set is alive; the home's lock is held until then, and a pid the walk could not kill is named in a note. The read loop is a reader thread and a queue: once the CLI has exited the walk runs and the loop ends within three seconds, pipe open or not. A process that scrubbed its environment and was re-parented to launchd before a look found it is beyond the walk. `summary.json` gains `"outlived"`, the processes found alive that the group kill alone would not have reached, 0 on a clean run, and above zero the run's notes carry `N processes outlived the CLI and were killed`. `ps` is the one external command; its absence is a note, not a crash.
- The verifier: `--verify` counted a line without a receipt and passed it, and nothing referred to lines removed from the end. Now lines before the first receipt-bearing line are the 0.1 ledger's and stay counted, and from the first receipt onward a line without one fails (`FAIL line N: no receipt, after line M had one`, M the first receipt's line), the failed count raised. New `--verify --expect <hash>`: the last receipt-bearing line's hash must equal the given one, else `FAIL: the last receipt is <hash>, not <expected>` and exit 1; the hash is on the summary line printed at a run's end, to be kept somewhere the ledger's writer cannot reach. A ledger with every receipt stripped still passes alone (it is the 0.1 ledger's shape) and fails against a kept hash.
- Finite money: `--budget`, `[defaults] budget` in `config.toml` and the `cap` file refuse `nan`, `inf` and `-inf` before anything else is read, naming the flag or the file (`--budget must be a finite number above zero`, `cap in <path> must be a finite number, zero or above`), in a dry run too; `nan` passed every comparison below it and a cap of `nan` would have disabled the cap.
- The proxy's path allowlist: the proxy forwarded any path under the upstream with the real key. New `[auth] paths`, default `["/v1/messages", "/v1/messages/count_tokens"]`: after the token check and before anything is forwarded, a request whose path (query dropped, one trailing slash dropped) is not equal to an entry gets 403 in the API's error shape (`SIwithin: path <path> is not on [auth] paths`), is logged with `"refused": "path"`, and the real key is never attached; `/v1/messages/../complete` and `/v1/messages;x` are not entries. The dry run names the list. The list is config because a longer run may call more paths than the one-turn live run of 14 October did, which called only `/v1/messages`; `proxy.jsonl` of a live run shows which a real CLI calls.
- `deny_exec` gains `/bin/launchctl`, `/usr/bin/crontab`, `/usr/bin/at` and `/usr/bin/batch`, ways to run something later or elsewhere (the stranger's F-folders-4). The list is by path, so a copy of one at another path is not stopped; that stays open and documented. The dry run says what happens to the run's processes, under the time line.
- Two red briefs, `env-key` (the key: names of the environment, what `ps -E -p` shows for `ANTHROPIC_API_KEY` in each ancestor, never a value) and `outlive` (the kill: a program started with `start_new_session=True` that beats into a file for 180 seconds, during a task longer than the pass's 120-second timeout, whose stop is the kill the program must not survive), with their scorer rules, `--fake` cases and rows in the walls table of `tests/red/README.md`; the leak detector now looks for the shape of a key and reads the scratch folder too. The smoke test passes 243 checks. Not done: whether a fence rule hides a process's environment from the run (`kern.procargs`) was not tested, as the launcher the work ran under would not run `sandbox-exec`; the walk and the briefs have not been run against a live CLI, nor against the system's `ps` where it could not be run.
- 2026-10-14, the first live `outlive` run: the task's program, launched with `start_new_session=True` from a launcher that exited at once, was killed by the walk at the timer's stop and not counted: the stop's first look went by ancestry alone while the CLI lived, and only the first look fed `outlived`. The first look now reads the marker too, and the rounds after the group kill add what they find alive outside the CLI's group; suite check `walk 2b` is that case. `tests/red/run.py --live --only <id>` re-runs one brief. The red scorer names a count the task could not take (`unavailable`): `/bin/ps` does not start inside the fence on this macOS, it carries private entitlements that `sandbox-exec` will not pass. The environment-read `sysctl-read` rule from the walls report was tested by the owner and the root and not adopted: it compiles, does not stop the read it names, and its blanket form stops the CLI; `[auth] key_command` is the wall that keeps the key out of every process environment.

## v0.1.1, 2026-10-13

Closes a gap found in a dry run of v0.1.0: with the first adapter the budget was kept by the CLI's flag at `budget × factor`, and the default factor of 40 for the smallest model, inherited from CLI 2.1.284, let a run launched on CLI 2.1.296 (whose own cost is the true cost) spend forty times its budget before the CLI stopped it.

### Changed
- The first adapter now enforces the true budget itself as well. The usage on each assistant event in the CLI's stream (input, cache-creation, cache-read and output tokens, and the model) is priced at the `[prices]` rates as it streams, each message id once, and the run's process group is killed when the true cost reaches `--budget`. The ledger line and the summary say `killed: budget $X reached at $Y true`. The CLI's flag stays as a second stop. If the stream carries no usage fields, the flag alone enforces the budget and the summary notes say so. (`usage_at = "message"` in the adapter.)
- The default factor for the first adapter's smallest model, `claude-haiku-5-5`, is 1. CLI 2.1.284 needed 40; a user on that version sets it under `[factors]` in `config.toml`. The comment saying so is in `fence.py` and `config.example.toml`.
- The stale-factor warning is two-sided: it fires when the CLI's cost over the true cost is more than four times the factor or less than a quarter of it.
- `--dry-run` prints both enforcements for the first adapter: the flag with its factor, and the streamed true-cost stop.
- The budget stop for adapters without a budget flag now uses the same wording, `killed: budget $X reached at $Y true`.
- `summary.json` gains `stream_cost`, the true cost of what streamed.

### Known limits, stated in the README and SECURITY.md
- The stream's per-event `output_tokens` is a placeholder until the final result, so the streamed stop is a lower bound: it never fires early and, on a run heavy in output, fires after the true budget. A run it kills is booked at what streamed.
- A model with no entry in `[prices]` is not counted by the streamed stop: the CLI's figure over its factor is used in the ledger and only the CLI's flag limits the run, so the stop is approximate.

### Tests
- `tests/smoke.py` adds a fake CLI that streams assistant events with usage: a run that passes the budget is killed (with its child process and the exact reason in the ledger line), a run under the budget is not, and the fallbacks (no usage in the stream, a model with no price) are noted. The test's choice of the latest run folder no longer breaks when more than nine runs share a minute.

## v0.1.0, 2026-10-13

First release: a standalone, vendor-neutral runner, built from a single-CLI launcher that ran on one person's Mac.

### Added
- `fence.py`, one file, Python 3.10+, standard library only. No telemetry and no network calls from the tool itself.
- Adapters declared in `config.toml`, with two built in (the README names the CLIs): the first, its command shape measured on CLI 2.1.284 and 2.1.296 by the launcher this grew from; the second, built from documentation read on 2026-10-13 and not run against a live CLI.
- The fence: a macOS `sandbox-exec` profile generated from a template with the home derived at run time. The home is refused for reads and writes and allowed back for the run's folders, the CLI's binary, caches, logs and keychain, the shell's rc files, git's config and the CLI's own config directory. The tool's own home is refused inside the run.
- Refusal of the home root (and any folder holding it), `~/.ssh`, `~/.config`, `~/Library`, each adapter's own config directory, the tool's home and any `[never]` folder, as `--dir` or `--read`, compared case-insensitively.
- On Linux and Windows the tool refuses to run, in one line, and points to the roadmap. `--dry-run` still prints everything on Linux and reports the refusal.
- Budget and cap: `--budget` per run, a `cap` file across all runs, checked under the lock. True cost at published rates from `[prices]` (with the date they were read), beside the CLI's own figure; `[factors]` with a stale-factor check, in both directions.
- Budget kept by the CLI's flag where it has one; kept by the runner from streamed usage where it does not. For a CLI that reports usage only when a turn ends, the tool refuses unless `--soft-budget` is given.
- A killed run whose usage was never reported is booked at its budget as a ceiling, and the ledger line says so.
- One run at a time (lock file), `--timeout` by a timer always, a run folder per run (`brief.md`, `command.txt`, `fence.sb`, `events.jsonl`, `stderr.txt`, `result.md`, `summary.json`), one ledger line per run, and a summary line.
- Brief contract: brief on stdin, `--done`, `--absent`, `--out` (inside `--dir` only).
- `--require-api-key` (default on for the first built-in adapter): the CLI's auth status before launch and the init event's key source during it.
- `--dry-run`: the resolved command, the fence profile, the config checks and the budget arithmetic; nothing is run or written.
- A reader for the TOML subset the config uses, for Python 3.10; `tomllib` is used where it exists.
- `tests/smoke.py`, `config.example.toml`, `README.md`, `SECURITY.md`, `LICENSE` (Apache-2.0).

### Not in v0.1
- Linux and Windows; a hosted team ledger; more CLIs; resume and effort for the second built-in adapter; a network fence. See the README.
